# 接手与上手指南

## 你拿到的是什么

这是可以独立运行和修改的源码，不包含作者的服务器账号、地址、文章、AI 对话、音频和数据库。无需以前的聊天记录或其他个人项目。MIT 许可允许在保留许可声明的前提下修改和分发。

## 准备自己的代码副本

在 GitHub 上 fork 项目，再 clone **自己的 fork**。如果项目尚未公开，等维护者完成发布；不要把含有私有历史的旧克隆直接镜像推到 public。

```bash
git remote -v
git status --short --branch
```

`origin` 应当是自己的 fork。原项目可以另设为 `upstream` 以获取更新。开发功能前新建分支，例如 `git switch -c feature/my-reader-change`。这份源码不授权访问或修改父辈、原作者的线上实例。

## 第一次运行

准备 Python 3.12+、ffmpeg（含 ffprobe）、用于扩展测试的 Node.js；无需前端构建工具。本地不用 Docker 也能运行。按 README 创建 `.venv`、安装依赖、生成 `.env` 并启动服务，命令在仓库根目录执行。不能同时启动两个指向同一数据库的应用进程。

用编辑器在本机查看 `.env` 的账号和密码，访问 <http://127.0.0.1:4780>。排查配置时向 AI 报告变量是否存在，不要让它把完整 env 抄进文档或日志。

按这个顺序验收：

1. `/health` 正常，网页可以登录。
2. 导入两三句不敏感文本，等待生成并播放。
3. 按[扩展说明](browser-extension.md)加载 `browser-extension/`，填写本地地址和自己的 `IMPORT_TOKEN`。
4. 导入已生成完成的测试对话；重复导入，确认已有回合不重复创建。

单元测试不验证外部 TTS 服务是否可用，也不保证 AI 网站当前 DOM 没变化，这两项需要真实网络和浏览器验收。

## 让 AI 编程助手接手

可以复制下面这段话，替换最后的需求：

> 这是我的 PocketReader 副本。先读 AGENTS.md、README.md、docs/ai-handoff.md 和与需求相关的设计文档。检查当前分支和已有修改，按上手指南确认本地能运行。只用我的本地测试数据，不读取或连接原作者服务器。解释准备修改的行为，完成代码、必要回归测试和文档，报告结果。真实地址和凭证只放在 Git 忽略的配置或仓库外，提交前运行公开内容检查。我的需求是：……

给 AI 四件事：当前行为、期望行为、复现步骤、必须保持的行为。例如修复增量导入时，说明另一朗读范围仍应能独立生成音频。

第一次建议从“增加一种声音”“调整排序”“修复漏掉小标题”这样的小任务开始，不同时重写界面、数据库和语音引擎。

## 修改和部署自己的版本

按 [CONTRIBUTING.md](../CONTRIBUTING.md)做回归，审查 diff，再推送自己的功能分支。数据库变更说明旧库兼容和回滚；采集规则使用合成 fixture，不能提交真实会话。

手机长期使用时，按 [部署说明](deployment.md)建立自己的 HTTPS 实例。各实例单独生成凭证，不复用开发配置或作者的账号。代码许可不包含第三方语音服务的可用性保证。

| 现象 | 先检查 |
| --- | --- |
| 缺少配置导致启动失败 | 已运行生成器，启动带 `--env-file .env`，变量不是 `CHANGE_ME` |
| 找不到 ffmpeg / ffprobe | 两个命令在当前 PATH 中 |
| 页面正常但语音生成失败 | 外部网络、提供方响应、条目错误信息；单测不调用真实 TTS |
| 扩展导入失败或 401 | 服务地址、该域名的授权、自己的 `IMPORT_TOKEN` |
| 扩展修改没生效 | reload 扩展之后还要刷新已打开的 AI 页面 |
| 手机连不上本地服务 | 手机的 `127.0.0.1` 指手机自身；长期使用需自己的 HTTPS 部署 |
| 推送被检查阻止 | 清理实际提交和历史，不关闭检查绕过 |

提 issue 用脱敏复现步骤和错误类型，不上传数据库、原始对话或带 token 的 URL。
